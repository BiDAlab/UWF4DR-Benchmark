# Model Evaluation (`eval/`)

This directory contains the evaluation scripts used to assess pretrained deep
learning models on the experimental test sets defined in the paper.

The evaluation code loads pretrained model weights, applies the appropriate
preprocessing pipelines, and computes standardized performance metrics on the
reconstructed test splits.

---

## Scope

The scripts in this directory are intended **exclusively for model evaluation**.
They do **not** implement model training, fine-tuning, or hyperparameter search.

All models are assumed to have been trained offline according to the experimental
protocol described in the paper and are evaluated here using fixed splits and
deterministic preprocessing.

---

## Evaluation Workflow

At a high level, the evaluation scripts perform the following steps:

1. Load a test split CSV file generated by the split preparation scripts in
   `src/prepare_splits/`.
2. Resolve the image paths listed in the CSV file on the local filesystem.
3. Apply the appropriate preprocessing pipeline (spatial or frequency domain).
4. Load the specified pretrained model weights.
5. Run inference on the test set.
6. Compute task-specific performance metrics.

---

## Input Requirements

Each evaluation script requires:

- A CSV file defining the test split (`test.csv`), generated by the corresponding
  `prepare_split_task_X.py` script.
- Pretrained model weights compatible with the selected architecture.
- Access to the locally downloaded UWF4DR dataset (images only).

The evaluation CSV files must contain the following columns:

- `image_path`: absolute path to the image file on the local system
- `label`: binary ground-truth label for the corresponding task

---

## Supported Models and Domains

The evaluation framework is designed to support multiple model families and
image representations, including:

- Convolutional neural networks (e.g., MobileNetV2, ResNet18)
- Vision transformer models (e.g., ViT-B/16)
- Retinal foundation models (e.g., RETFound)

Two input domains are supported:

- **Spatial domain** (RGB images)
- **Frequency domain** (2D DFT magnitude representation)

Task-specific and model-specific input requirements (such as image resolution)
are defined at evaluation time.

---

## Metrics

The evaluation scripts compute standard binary classification metrics, including:

- Area Under the ROC Curve (AUROC)
- Area Under the Precision–Recall Curve (AUPRC)
- Sensitivity
- Specificity

Threshold-dependent metrics are computed using an operating point derived from
the ROC curve.

---

## Usage Notes

- Evaluation scripts are expected to be executed from the **root of the
  repository**, preferably using Python module execution (e.g., `python -m`).
- No intermediate results or predictions are stored unless explicitly modified
  by the user.
- Numerical results may vary slightly depending on hardware and software
  environments, but the evaluation procedure itself is deterministic.

For a complete description of the experimental protocol and how evaluation fits
into the overall workflow, refer to `docs/reproducibility.md`.
